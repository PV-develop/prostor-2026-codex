# Дизайн-система «Простор»

Локальная библиотека находится на `/design-system/`. Выберите блок, переключите вариант и откройте пример отдельно, чтобы проверить его на полной ширине экрана. Ссылка с фрагментом сохраняет выбор, например `/design-system/#faq`.

## Основы оформления

| Элемент | Правило |
| --- | --- |
| Цвет | Фон страницы — `--color-paper`, основной текст — `--color-ink`, акцент — `--color-red`, тёмный акцент — `--color-red-deep`. Поверхности и карточки используют `--color-surface` и `--color-card`. |
| Типографика | Steelfish для крупных заголовков, Onest для текста, JetBrains Mono для кнопок и служебных подписей. Уровень HTML-заголовка выбирается по структуре страницы. Начертание и размер берутся из шкалы `--type-h1` … `--type-h6`, `--type-body`, `--type-label`, `--type-button`. |
| Контейнер | `--gutter` выравнивает секции по общей вертикали. На широком экране поле составляет минимум 48 px, при ширине до 1000 px — 30 px, до 680 px — 21 px. |
| Интервалы | Внешний ритм секций задаёт `--section-space-y`, расстояние от заголовка до содержимого — `--section-content-gap`. Внутри используйте шкалу `--space-*`. Учитывайте поля самого компонента. |
| Заголовок и пояснение | Общая пара использует `section-heading-pair`, `section-heading-pair__title` и `section-heading-pair__subtitle`. При ширине до 760 px колонки складываются вертикально. |
| Действия | Основную ссылку первого экрана услуги передавайте через `primaryCTA`, дополнительную — через `secondaryCTA`. Переход оформляется ссылкой, отправка формы — кнопкой. |
| Карточки | У кейсов есть изображение и метрика, у этапов — срок и результат. Вариант ProcessCards с `carousel` поддерживает горизонтальную прокрутку на телефоне. Используйте `inset={false}`, если боковые поля задаёт внешняя секция. |
| Формы | Для консультации используется ExpertContactForm, для заявки с описанием проекта и вложением — Contacts. Подписи, валидация и интерактивные состояния проверяются на живом примере. |

Значения токенов находятся в `src/styles/global.css`. Блоки услуги используют `src/styles/performance.css`. Общая оболочка страницы — BaseLayout, клиентское поведение меню и форм подключается через `src/scripts/home.ts`.

## Библиотека блоков

| Блок | Страницы | Компонент и изменяемое содержимое |
| --- | --- | --- |
| Первый экран | Обе | HeroLight и ServiceHero используют HeroContent и SiteHeader. У ServiceHero настраиваются тексты, действия и оформление. |
| Шапка | Обе | SiteHeader. Параметр activeSection выбирает текущий раздел. |
| Каталог направлений | Обе | Services и ServiceChannels используют DirectionRows. Строка содержит название, описание, теги, ссылку и необязательный бейдж. Составные секции добавляют вводную часть и акцентную строку. |
| Кейсы | Обе | Cases принимает подборку items. У каждой карточки стабильный slotId для image-slot, изображение, ссылка и числовой результат. |
| Процесс в карточках | Обе | ProcessCards принимает items. В библиотеке доступны сетка и карусель. |
| Консультация эксперта | Обе | ExpertContactForm. Якорь задаётся через id, заголовок — слотом heading. На главной форму подключает ProcessLead. |
| Команда и отзыв | Главная | TeamReviews объединяет карточки команды и цитату клиента. |
| Контакты и заявка | Обе | Contacts объединяет форму, переход к брифу, контактные данные и мессенджеры. Для текстов формы доступны слоты heading и description. |
| Подвал | Обе | Footer входит в Contacts и доступен отдельно. |
| Задачи бизнеса | Услуга | BusinessTasks принимает список ситуаций и показывает их рядом с фотографией и ссылкой на консультацию. |
| Матрица решений | Услуга | ServiceDecisionMatrix принимает формулировки критериев и пояснения. |
| Распределение бюджета | Услуга | BudgetCriteria показывает принцип распределения и массив критериев с выделенной карточкой. |
| Метрики | Услуга | Metrics принимает названия и описания показателей. |
| Витрина аналитики | Услуга | AnalyticsShowcase принимает изображение, его текстовую альтернативу и описание. |
| Этапы на временной шкале | Услуга | StageTimeline принимает этапы со сроками, короткими названиями и иллюстрациями. Слайд меняется при прокрутке. |
| Стоимость | Услуга | Pricing принимает основные статьи расходов в items и дополнительное предложение в extra. |
| Частые вопросы | Услуга | Faq принимает массив пар q и a. Ответ открывается через details. |
| Статьи | Услуга | BlogArticles принимает заголовок, подборку публикаций и ссылку на раздел. |
| Сертификаты | Услуга | Certificates принимает изображения с текстовыми альтернативами. |

## Как собрать страницу

1. Выберите блоки из библиотеки. Тексты, ссылки и списки храните рядом с данными страницы. Примеры находятся в `src/data/performance.ts`, `src/data/home-directions.ts` и `src/content/cases/`.
2. Импортируйте Astro-компонент и передайте параметры из его типа Props. Для BusinessTasks, ServiceChannels, Metrics, StageTimeline, Pricing и Faq можно заменить заголовок и пояснение через именованные слоты.
3. Согласуйте якоря кнопок и целевых секций. Задайте уникальные ID для новых слотов изображений. Проверьте компоновку и интерактивное поведение на десктопе и телефоне.

```astro
---
import Faq from '../components/blocks/Faq.astro';
const questions = [{ q: 'С чего начать?', a: 'Оставьте заявку, чтобы обсудить задачи проекта.' }];
---
<Faq items={questions}>
  <span slot="heading">Вопросы о сотрудничестве</span>
</Faq>
```

## Как расширять систему

Новый набор текстов передавайте существующему блоку. Вариант оформления добавляйте в его запись библиотеки. Если задаче нужна другая структура или поведение, добавьте компонент, строку в карту, запись в `src/data/design-system.ts` и рабочий пример в `src/pages/design-system/[example].astro` в одной группе правок.

## Страницы из Markdown

Для SEO-страницы создайте файл в `src/content/seo/`: имя файла задаёт адрес `/services/<имя>/`. Заголовок вкладки и описание поиска задаются полями `title` и `description`. Секции описываются списком `blocks` в YAML между строками `---`. Порядок строк списка задаёт порядок секций. Рабочий образец — `src/content/seo/seo-internet-magazinov.md`.

Для статьи создайте файл в `src/content/articles/`. Текст после YAML поддерживает обычные заголовки, абзацы, ссылки, изображения и списки Markdown. В шаблоне сначала выводятся заголовок, описание, необязательная обложка и текст, затем — блоки из списка. Рабочий образец — `src/content/articles/kategoriya-dlya-seo.md`. Обе пилотные страницы используют `noindex: true`.

| type | Что задаёт редактор |
| --- | --- |
| hero | heading, description и primaryCTA. Можно добавить accent и secondaryCTA. |
| tasks | heading, description, photo (src и alt), список items (title и description). Подпись caption и кнопка cta необязательны. |
| cases | heading, список caseIds в нужном порядке, необязательная ссылка cta. |
| faq | heading, description, список items (question и answer), необязательная ссылка cta. |
| contacts | heading, description, необязательная надпись кнопки submitLabel. В brief можно передать заголовок, описание и ссылку дополнительной карточки. Телефоны и почта общие для сайта. |

У ссылок есть поля `label` и `href`. Строку с якорем в YAML заключайте в кавычки, например `href: '#contacts'`. Изображения размещайте в `public/`, путь указывайте от корня сайта. Каждый кейс хранится один раз в `src/content/cases/<ID>.md`. Его изображение, подпись и числовой результат обновляются во всех подборках. Существующие значения `slotId` сохраняйте при правке материалов.

Эти пять типов доступны в библиотеке с вариантом «Из Markdown». Схемы находятся в `src/content/schema.ts`, сопоставление типов и Astro-компонентов — в `PageBlocks.astro`. Для следующего типа добавьте схему, подключите компонент к PageBlocks и покажите вариант с редакторским контентом. Проверьте длинный заголовок, короткий список, отсутствующую необязательную кнопку, целевые якоря, консоль браузера и сборку.
