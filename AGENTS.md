# Инструкции проекта «Простор»

## Репозиторий и публикация

- Основной репозиторий этой кодовой базы: `PV-develop/prostor-2026-codex` (`https://github.com/PV-develop/prostor-2026-codex`), ветка по умолчанию — `main`.
- Не изменять прежний репозиторий `PV-develop/prostor-2026`.
- Не публиковать сайт и не создавать production-релиз без отдельного явного указания пользователя.
- Commit, push и создание Pull Request выполнять после утверждения пользователем логической группы правок.

## Текущая архитектура

- Astro со статической генерацией и TypeScript.
- `src/pages/` содержит маршруты, `src/layouts/` — общую HTML-оболочку, `src/components/` — переиспользуемые блоки, `src/styles/` — общие стили, `src/scripts/` — необходимую клиентскую логику.
- `public/` содержит локальные ресурсы сайта. Работающий сайт не должен зависеть от внешних CDN.
- `reference-claude-design.html` — сохранённая копия исходного HTML-экспорта для сверки. `support.js` — сгенерированный runtime экспорта; вручную его не редактировать и не подключать к новым страницам.
- Слоты изображений сохраняют уникальные ID и контракт `<image-slot>`; исходный `image-slot.js` вручную не редактировать.
- Кейсы и статьи планируются в Markdown; типовые блочные страницы — структурированными данными; SEO-поля хранятся рядом со страницей, редиректы — отдельно.

## Команды

Требуется Node.js 22.23.4 или новее.

- `npm install` — установка зависимостей.
- `npm run dev` — локальный сервер разработки.
- `npm run check` — диагностика Astro и TypeScript.
- `npm run build` — статическая production-сборка в `dist/`.
- `npm run preview` — локальный просмотр собранного сайта.

## Правила работы

1. Работать в локальной копии этого репозитория и перед крупным этапом сверять её состояние с GitHub. Не перезаписывать незакоммиченные изменения.
2. Визуальные правки выполнять локально, не коммитить каждую промежуточную итерацию.
3. Сначала переиспользовать существующие Astro-компоненты. Новые универсальные блоки добавлять, если они пригодятся на нескольких страницах.
4. Сохранять утверждённый внешний вид и действующее поведение; проверять затронутые десктопные и мобильные варианты, локальные ресурсы, переполнение по ширине и ошибки браузера.
5. Для визуальных итераций готовить локальный preview и сообщать его расположение. Preview не является production-публикацией.
6. В конце сообщать, что изменилось и как проверено. Если проверка или preview недоступны, указать это.
7. Commit и push выполнять только после отдельного одобрения пользователя.
